# AGENTS.md — frontend

Next.js (React) storefront and marketing site. See the workspace-level
[`AGENTS.md`](../workspace/AGENTS.md) and [`PROJECT_BRIEF.md`](../workspace/PROJECT_BRIEF.md)
for full system context; this file covers what's specific to this repo.

## What this repo is

Homepage, marketing pages, product listing/detail pages, cart, checkout
redirect, order confirmation page. Talks to `backend` only over HTTP
(`GET /products`, `POST /checkout`, etc.) via a typed client generated with
**Orval** from the backend's OpenAPI spec, using **React Query**.

## This is the only AI-editable repo

This is the sole repo the client-facing AI orchestrator (`PROJECT_BRIEF.md`
§10) ever has write access to — its scoped GitHub App is installed here and
nowhere else. That makes the guardrails below load-bearing, not stylistic:

- **Contains NO secrets, NO database access, NO admin code, NO Stripe keys.**
- The orchestrator's `commit_and_push` tool is hardcoded to push to the
  **`client-preview`** branch only — never `main`.
- The orchestrator's `edit_file`/`read_file` tools are restricted to an
  allowlist of directories (e.g. `src/components`, `content/`) enforced in
  the orchestrator's own code. Config files (`next.config.js`, CI workflows,
  env handling) are off-limits even if asked.
- `client-preview` reads **mock data only** (Orval/MSW mock server off the
  OpenAPI spec) — never real stock/prices/orders.

These rules constrain the *runtime* orchestrator. As a human-directed coding
agent building this repo, you are not bound by the file allowlist — but do
not weaken or remove the guardrails above without the owner's explicit
sign-off, since they're the point of the project.

## Branches & deploys

- **`main`** → `õtekse.ee` (production). **Protected — changes land only via PR.** Never push to it directly.
- **`development`** — where all human and dev-agent work happens (directly or via feature branches off it). PR from here into `main`.
- **`client-preview`** → `preview.õtekse.ee`. **The runtime orchestrator's branch, and only its.** It is disposable: reset (force-pushed) to `main` after every promotion PR merges, and at the start of any client session where it has diverged. Nothing of value may ever live only on this branch — never park manual work here. See `PROJECT_BRIEF.md` §10, "The `client-preview` lifecycle".

## Language / i18n

Estonian (`et`) is the default locale; English (`en`) is also supported. The
locale is auto-selected (users in Estonia / Estonian-language browsers get
Estonian, everyone else English) with a manual switcher. i18n is built in from
the start — never hardcode user-facing strings.

## API client (Orval) — committed, deterministic

The typed client + React Query hooks + MSW mocks are **generated by Orval and
committed to this repo**, along with the OpenAPI spec snapshot they were
generated from. Regeneration is a human action (run Orval against the live
backend when the API changes) — builds, CI, and the AI sandbox only compile
committed code, with no spec fetch and no backend or network dependency.
**Never hand-edit generated files**; CI regenerates from the committed spec
and fails on any diff.

## CI

- Typecheck, lint, build, tests.
- Smoke check: homepage renders, checkout redirect is exercised **against the
  MSW mocks, never the real backend**.
- Orval no-diff check: regenerate the client from the committed spec snapshot
  and fail if anything changes (catches hand-edited generated code).
- No secrets in CI — this repo holds none.

## Setup & commands

Stack: **Next.js 16 (App Router) + React 19 + SCSS + TypeScript**, npm, Node 22 (see workspace `AGENTS.md` conventions). Data via **React Query + Orval**, i18n via **next-intl**, preview mocks via **MSW**. Styling is SCSS + CSS custom properties only — no CSS/utility framework (see "Styling").

```sh
cp .env.example .env.local        # set NEXT_PUBLIC_API_MOCKING=enabled to run on mocks
npm install
npm run dev                       # http://localhost:3000
```

Commands: `npm run build`, `npm run lint`, `npm start`.

API client workflow (see "API client" above):
- `npm run spec:pull` — refresh `openapi.json` from the backend (`API_SPEC_URL=…` for the live API; defaults to copying `../backend/openapi.json`).
- `npm run api:generate` — regenerate the typed client, hooks, and MSW mocks into `src/api/generated`. Commit `openapi.json` and the generated output together.
- `npm run api:check` — CI drift gate: regenerates and fails if `src/api/generated` changes.

## Conventions

- **Routes live under `src/app/[locale]/`.** Use the locale-aware `Link`/`useRouter` from `@/i18n/navigation`, never bare `next/link` / `next/navigation`, so the active locale is preserved. All user-facing strings come from `messages/{et,en}.json` via `next-intl` — never hardcoded.
- **Data fetching is client-side** through the generated React Query hooks (`useProductsController…`). This is deliberate: it lets MSW intercept in `client-preview`, so the preview renders mock data and never hits the real backend (`PROJECT_BRIEF.md` §10). Don't fetch store data in server components.
- **Money is integer cents**; format with `formatPrice()` from `@/lib/format`. Never trust these client-side prices for payment — the backend re-validates at checkout.
- **Cart is client-only** (`@/lib/cart`, localStorage). No server cart.
- `src/api/generated/**` is generated and git-ignored by ESLint — never hand-edit it.
- **Editable content collections** (concerts, members, teaser items, asset paths) live in `src/content/` as typed modules with `{et, en}` fields — the allowlist-friendly directory the runtime orchestrator will be scoped to (`PROJECT_BRIEF.md` §10). UI strings stay in `messages/`.

## Styling (design system)

The visual system is extracted from the Claude Design source (see "Design source"). **One system: plain CSS custom properties for tokens + SCSS for everything else — no CSS/utility framework.**

- **Single token source:** the `:root` block in `src/app/globals.css`. Every raw design value (color, font, size, radius, shadow, layout metric) is a `--token` defined there and ONLY there, then consumed elsewhere via `var(--token)`. Being ordinary custom properties, they are always present at runtime — SCSS reads them directly. **Never write a hex color or magic px value anywhere else.** Need a new value? Add a token first. (`globals.css` also holds the minimal reset and the base `html`/`body`/`main` rules — this project ships no framework preflight.)
- **SCSS modules for all component styling:** co-located `*.module.scss` importing the shared mixins (`@use "../styles/mixins" as *;` — relative path). Mixins (`pill`, `overline`, `display-heading`, `bordered-card`, `card-hover`, `rotated-tag`, breakpoints `from`/`until`, `focus-ring`, `reduced-motion`) read the token custom properties; they never define values. Keep truly one-off inline styles rare; a pattern used twice belongs in a mixin or module class.
- **Cross-page commerce patterns** live in `src/styles/ui.module.scss` (`page`, `pillDark`, `notePanel`, `inkLink`, `input`, `lineItems`, `totalRow`, `muted`, `actions`, …) — reuse before writing new ones. Each commerce page keeps its layout-specific bits in a co-located `page.module.scss`.
- **Motion:** any animation/parallax must be disabled under `prefers-reduced-motion` (use the `reduced-motion` mixin; see `Hero.tsx` for the JS-side check).
- **In-page anchors:** the fixed nav is cleared by `scroll-margin-top: var(--nav-offset)`, applied to `section[id]` globally in `globals.css` — add `id`s to sections, not ad-hoc offsets.
- **Content images always go through `SmartImage`** (`src/components/SmartImage.tsx`): it renders the token-styled loading skeleton (cream shimmer on sand, disabled under reduced-motion) and the wheat-mark placeholder for missing/failed images. Decorative CSS backgrounds (hero layers, wheat waves) are exempt.
- **Images:** all design-asset paths come from `src/content/assets.ts`. Optimized web images in `public/images/` are generated by `npm run images:build` (`scripts/optimize-images.mjs`, sharp) from originals in `assets-src/` (gitignored; originals also live in the owner's Google Drive and the Claude Design project). To change an image: original → `assets-src/`, rerun the script, commit the output. Never put multi-MB originals in `public/`.
- The `NEXT_PUBLIC_API_MOCKING=enabled` build (client-preview) intentionally skips SSR paint until MSW is ready; production builds render fully on the server.

## Locale resolution

The middleware — not next-intl — owns the decision of which language a visitor
gets. `localeDetection` is `false` in `src/i18n/routing.ts`; note that this also
stops next-intl reading the `NEXT_LOCALE` cookie, which is why the middleware
reads it directly.

Precedence: **remembered choice (`NEXT_LOCALE` cookie) → IP geo (Estonia → `et`)
→ Accept-Language (Estonian-preferring → `et`) → English.** Crawlers skip geo
entirely and get `defaultLocale`, so indexing never depends on where a bot
crawls from.

- The decision itself is a pure, unit-tested function: `src/i18n/resolve-locale.ts`.
- Geo runs in `src/app/api/locale/route.ts` (`runtime = "nodejs"`) because the
  GeoIP database is read from disk, which the Edge runtime cannot do. A
  first-time visitor costs one redirect; the cookie handles everyone after.
- The database is DB-IP Lite, downloaded into gitignored `geoip/` by the
  `prebuild` script on every build. **Everything fails soft** — a missing or
  unreachable database degrades to Accept-Language, never a broken build.
- `X-Forwarded-For` is client-spoofable here. That is fine for choosing a
  default language and **must never** be used for auth, rate limiting, or audit.

## Analytics and privacy

Analytics is self-hosted Umami, which is **cookieless** — it sets nothing on the
visitor's device. Together with the strictly-necessary `NEXT_LOCALE` cookie and
build-time-self-hosted fonts (`next/font/google` downloads at build time, so the
browser never contacts Google), this is why the site needs no consent banner.
See `workspace/docs/superpowers/specs/2026-07-27-public-launch-design.md`.

A privacy policy is still required — GDPR Art. 13 transparency is a separate
obligation from ePrivacy consent, and it applies because Umami processes IP
addresses server-side. It lives at `src/app/[locale]/privacy/`.

**Consent tripwire — adding any of these makes a consent banner legally
required, so do not add them without telling the owner first:**

- Google Analytics or any third-party analytics script
- advertising or retargeting pixels (Meta, Google Ads, …)
- YouTube, Vimeo, or Spotify embeds
- session replay (Hotjar and similar)
- any external script or iframe that sets a cookie

Loading fonts or images from a third-party CDN is also a change of substance —
it exposes visitor IPs to that provider. Keep assets on our own origin.
